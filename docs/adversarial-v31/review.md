# Arena Criolla adversarial review, v31

Reviewed 2026-10-17. Two new reviewers were assigned independently using `gpt-6-luna` with `xhigh` reasoning: one for character creation, one for the game. The root agent reproduced and integrated fixes and checked the resulting code. The review boundary was the working application, including untracked files, rather than only the small tracked Git diff. This repository is Arena Criolla, not the Django/payment platform used as an example in the supplied rubric.

The creation feature is a LangGraph generation pipeline. There is no retriever, vector index or RAG corpus. Tests used temporary SQLite databases, temporary uploads, ephemeral local ports and simulated providers. The installed OpenAI SDK was also exercised through a local HTTP server. No paid generation request was made.

## Findings repaired

Severity is the impact of the original behavior. Confidence is high for the following reproduced cases; first-design validation is explicitly marked as hardening.

| Severity / confidence | Location in the repaired implementation | Concrete failure scenario and resulting behavior |
| --- | --- | --- |
| P1 / high | `server/creator/worker.ts:138` | A provider failed and the following SQLite failure-status write failed too. The former unhandled rejection killed Node and every active fight. The worker now contains the failure and stops further generation while the game stays available. |
| P1 / high | `server/creator/worker.ts:98`, `server/creator/router.ts:403` | Thirty submissions were accepted behind one stalled provider call. They could accumulate paid work without a global bound. Defaults now allow two executions, twelve total reservations and two uploads, with persistent rolling attempt budgets and overload responses. |
| P2 / high | `server/creator/router.ts:419` | Same-account parallel requests previously buffered photos before rejecting duplicate creation. The account/global upload reservation now happens before Multer reads file bodies. Unsupported decoded image formats, oversized files and malformed images fail before provider work. |
| P2 / high | `server/creator/pipeline.ts:239` | An image was written successfully, but recording its path failed. Retrying previously requested a second paid image. Completed images now use atomic rename and are recovered from disk without another draw. |
| P2 / high | `server/creator/pipeline.ts:264`, `server/creator/sprites.ts:18` | Invalid generated bytes were cached and every retry reused the same broken file. Decode errors become validation failures, remove the invalid source and permit an explicit redraw. |
| P2 / high | `server/creator/database.ts:91` | A failed character INSERT consumed a daily attempt even though no job was accepted. Quota reservation and job insertion/retry state update now share a transaction and roll back together. |
| P2 / high | `server/creator/router.ts:485` | A second user held a multipart body while another job's persistence error stopped the worker. Finishing the upload previously returned 202 for a row that could never run. A final availability check now rejects it with 503 without reserving an attempt or inserting a job. |
| P3 / high | `server/creator/worker.ts:126` | A queued job could wait five 300-second waves, then receive another 300 seconds of runtime. The deadline now starts at acceptance, includes queue wait and prevents expired work from reaching the provider. Late provider responses cannot advance a timed-out job. |
| P2 / high | `server/creator/router.ts:249`, `server/creator/router.ts:561` | Concurrent publish/delete requests could act on stale character state; concurrent catalog writes could overwrite each other. Per-character mutation locks and serialized atomic snapshots keep retirement and publication consistent. |
| P2 / high | `server/creator/router.ts:228` | SQLite publication could commit, then writing the derived JSON snapshot failed, suppressing the WebSocket update and reporting failure for a published character. SQLite remains authoritative: peers receive the committed catalog, and snapshot errors are logged for repair. A real filesystem obstruction regression verifies this behavior. |
| P2 / high | `server/index.ts:555` | Shutdown closed SQLite while a password hash or upload handler was still running. Shutdown now stops admission, drains HTTP with a five-second connection deadline, then closes the database. Repeated shutdown is idempotent. |
| P3 / high | `server/creator/router.ts:298` | Any failed user INSERT was reported as an already-used email. A storage failure now returns a server error; after repair the same address can sign up normally. |
| P2 / high | `server/index.ts:309`, `server/index.ts:136` | One peer's list request broadcast the entire room list to every peer. In a 64-peer fixture, 180 requests attempted 11,520 recipient sends. Requests are now requester-only, limited to five per second; actual list changes are coalesced and repeated no-op controls are suppressed. |
| P2 / high | `server/index.ts:333`, `shared/room-code.ts:1` | Private rooms used a 24-bit code, making invitation guessing feasible under sufficient probing. Invitations now use 128 random bits and the URL/form/server share a 32-hex-character contract. Distributed attack throughput was not benchmarked. |
| P2 / high | `server/index.ts:236` | An upgrade to an unknown path left an unhandled socket outside the normal WebSocket client cap. Invalid upgrades now return an error and destroy the socket after flushing; Vite HMR remains allowed in development. |
| P2 / high | `server/index.ts:85` | A slow client could silently lose its start message, then receive state frames while remaining in the lobby without its player index. Replaceable state/list updates can be dropped; unsendable essential messages now disconnect the peer and trigger room cleanup/reconnect. |
| P3 / high | `server/index.ts:465`, `server/ticker.ts:1` | A simulation step per rounded Node timer callback ran faster than the advertised 60 Hz. A monotonic fixed-step accumulator now controls simulation time and caps catch-up at five steps. Deterministic tests verify 3,600 steps in 60,000 ms at several callback cadences. |
| P3 hardening / high | `server/creator/pipeline.ts:196` | A replacement provider could bypass provider-local design validation. Initial and resumed designs are now validated at the graph boundary. An invalid first response makes zero sprite requests. |

## Open findings and operating constraints

| Severity / confidence | Location | Concrete scenario and remaining consequence |
| --- | --- | --- |
| P2 / high | `server/creator/router.ts:641` | An owner publishes and then removes a character. Its detail route becomes 404, but its old sprite URL still returns 200 to anonymous visitors indefinitely. Archived artwork also keeps consuming disk. Preservation for ongoing matches is intentional; expiration or an owner-controlled purge has not been implemented. |
| P3 / high | `server/creator/worker.ts:146` | A temporary persistence outage causes both generation and its compensating status write to fail. The worker halts safely, but will not resume after storage recovers until the process restarts. Capabilities report unavailable; the arena health endpoint stays healthy by design. Monitor the workshop endpoint and logs, repair storage and restart. |
| P3 / high, conditional on unsupported deployment | `server/creator/worker.ts:82` | Running two instances would create two independent queues/capacity counters and separate in-memory room sets. This release requires one Node process with persistent SQLite/files; it is not a distributed queue or horizontally scaled game server. |
| P2 / medium | `server/creator/provider.ts:38` | A timeout or connection loss happens after an upstream provider accepted an image request. Local cancellation cannot establish whether it completed or was billed. Automatic SDK retries are disabled and cached completed images are reused, but exactly-once external billing is not established. No live billing outcome was tested. |

The host had only about 248 MiB available on its 96 GiB filesystem. `docker build` failed at `Dockerfile:4` with `ENOSPC` during `npm ci`. This is a verified environment blocker: the production image build/boot remains unvalidated locally. No unrelated images, caches or user files were removed to create space.

## Verification and its limits

- Final integrated run: **538 tests passed**, zero failed/skipped/cancelled. This includes the existing 41 individual character audits plus new adversarial, recovery, SDK-contract and scheduler tests.
- TypeScript/Vite production build passed. Asset validation passed for all 41 fighters and 328 poses. Production dependency audit reported zero advisories at review time.
- Thirty local admission attempts with providers deliberately stalled admitted twelve and rejected eighteen. Two workers were active; ten jobs waited. The integrated run measured accepted-response p50 16.5 ms/p95 102.5 ms. This measures local admission, not image generation.
- Two independent LangGraph runs, including real sprite packing and file writes, completed while 108 health requests ran four at a time. In the integrated suite, p50 was 7.3 ms, p95 31.6 ms and maximum 71.5 ms. Smaller isolated runs were faster. Providers supplied fixture images; this is not an upstream or production SLA.
- The 64-peer/32-room flood fixture returned five list replies and zero unrelated peer broadcasts for 180 requests. Reply payload was 8,946 bytes, 44,730 bytes total. The 24-room/48-peer fixture checked room isolation, continued ticking, malformed messages and a 5 KB frame closing with code 1009. Wall-clock tick rates must use actual measured elapsed time, not assume a scheduled 1,000 ms timer fired exactly on time.
- Browser checks use the native collaborative preview. CSS viewport and synthetic-touch results do not establish physical iOS/Android behavior or real mobile network latency. See the game review for its exact interactions and sizes.
- The real SDK's HTTP contract, signal cancellation and disabled retry behavior passed against an ephemeral mock upstream. The image request was checked against [official OpenAI image-edit documentation](https://developers.openai.com/api/reference/resources/images/methods/edit); transparency for the configured image model remains a preview capability and model/account output was not exercised live.

**CI does not validate live provider availability, generation quality/likeness, external billing/cancellation outcomes, physical mobile browsers, distributed deployments or a public Internet load profile.** The newly added workflow runs tests, assets, build and a production-container HTTP smoke test. That hosted workflow has not run in this review; its local Docker equivalent was blocked by the host disk.

RISKIEST LINE: `server/creator/router.ts:641` — archived generated artwork remains anonymously downloadable with no expiration or owner purge, so removal is not complete revocation and retained files accumulate.
